# Lesson 06 — Programming Patterns & My Blocks

**Concepts:** organizing code so the pilot can find the right program in
seconds and any team member can modify any run.

## Warm-up (5 min)

Show them a 60-block wall of code. Ask: "The judge asks what this does.
Answer in 10 seconds." Then: "What if it were 5 named chunks?"

## Teach (10 min)

- **One program per run**, named consistently (`R1-biobay-v3`), selected from
  the program list on the hub — the pilot never edits code at the table.
- **My Blocks (functions):** wrap reusable maneuvers — `alignWall()`,
  `lineToDock()`, `dropArm()` — then a run reads like a story.
- **Program flow discipline:** sounds/screen labels at run start so the pilot
  confirms the right program is loaded. Wait-for-button-start if the team
  wants a consistent launch moment.
- (If any team moves to Python: same structure, `def` instead of My Blocks.
  Word Blocks are entirely sufficient for this age; switch only if the kid
  is genuinely excited.)

## Hands-on (25 min)

1. Refactor the team's longest existing program into My Blocks.
2. Add start sounds/labels to every existing program.
3. Rename all programs to the agreed convention in [code-log.md](../code-log.md).

## Debrief (5 min)

- Trade robots/programs: can your teammate run *your* run from the hub alone?

## Success criteria

☐ Every run program named per convention, with start labels
☐ At least 2 My Blocks in active use
☐ Any kid can load and launch any run unaided
