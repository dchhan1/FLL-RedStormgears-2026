Week-by-Week Season Arc

Goals, exit criteria, and coach focus per phase. For a small mixed-experience team of four (Andrew, Eric, Emily — 6th; Ethan — 5th; 2×/week, 2 hrs).

Phase 1 · Kickoff (weeks 1–2): buy-in and foundations

Goal: team identity, norms, and everyone can drive the robot.

  • Kids write team norms themselves (they'll follow their own rules, not yours)
  • Build all mission models + set up field — the fastest way to learn the theme
  • New members: hub, motors, ports, first program ("drive 50 cm and stop")
  • Returning members: refresh + mentor the new kids (teaching = learning)

Exit criteria: norms posted, field complete, every kid has run a program.

Coach focus: set the kid-led tone now — you ask questions, they decide.

Phase 2 · Early season (weeks 3–4): first win + problem picked

Goal: one complete mission end-to-end; project problem chosen.

  • Robot: drive straight with geometry (rotations math), turns, then a real mission
  • Project: theme → problems they care about → one precisely defined problem
  • Do the "season math": list every mission's points and difficulty (kids do this)

Exit criteria: mission #1 scores reliably 3× in a row; problem statement written.

Coach focus: the first completed mission is the season's biggest motivator — engineer an early win. On project, widen then narrow: 20 ideas → 1.

Phase 3 · Mid-season (weeks 5–8): parallel tracks

Goal: 2–3 reliable missions; research + expert contact done.

  • One meeting skews robot, the other project (small team: 60/40 splits fine)
  • Robot: alignment jigs (walls, lines), run sheets begin, code saved by date
  • Project: research log, then interview an expert — this transforms judging

    • credibility. Email template in 04-Innovation-Project

Exit criteria: Run 1 written; expert interview scheduled or done.

Coach focus: guard against rebuild-itis (scrapping the robot for a "better" idea). Rule: improve or add, don't restart, after week 6.

Phase 4 · Integration (weeks 9–11): make it real

Goal: chained full runs; solution prototyped and tested.

  • Robot: attachments that swap fast, missions chained into timed runs, log scores

    • every session (date, run, points, what failed) — reliability data is gold in Robot Design judging

  • Project: build the prototype/model, get feedback from expert or real users,

    • iterate once and document what changed and why

Exit criteria: full Run 1 completes under the match clock; feedback received.

Coach focus: mid-season rubric self-check with the kids against the official rubrics — let them find their own gaps.

Phase 5 · Rehearsal (weeks 12–13): lock and polish

Goal: consistency and communication.

  • Lock the run list: no new missions, only reliability reps
  • Presentation written by kids, every kid speaks, rehearse with a timer
  • Mock judging: grab another adult to play judge for all three sessions
  • Mock tournament: full 2:30 matches with field reset by someone else

Exit criteria: best-of-3 mock runs within a few points of each other.

Coach focus: manage nerves, not content. Confidence and Core Values win rooms.

Phase 6 · Tournament week (week 14): taper

  • Light practice only. Charge everything. Pack early (see 07-Tournament)
  • Kids present to parents once — a friendly audience builds huge confidence
  • Talk explicitly about Gracious Professionalism: cheer for other teams

If you're behind (you will be, somewhere)

  1. Cut robot scope, never presentation practice
  2. A 2-mission robot that works beats a 6-mission robot that doesn't
  3. Project can be smaller but must be complete: problem → research →

    4. solution → feedback → shared
